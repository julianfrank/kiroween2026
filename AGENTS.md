# AGENTS.md: Scary Money Manager

Status and code map for agent sessions. Read this first, and update the **Status** section after every task. The rules (decisions you must not change, rules from real bugs, working rules) are in `.kiro/steering/rules.md`; product, tech and structure are beside it in `.kiro/steering/`.

## What this is
A single-file HTML money manager for Chrome, built for Kiroween 2026. It uses Chrome's on-device Prompt API (Gemini Nano) to turn plain text into double-entry ledger entries. Values are encrypted with a session password. The theme follows net worth. The original brief is `ideas/.ignore/PROMPTS.md`.

## How the code is organised (`src/`)
- **Startup (`App.tsx`):** AI readiness (`ai/readiness.ts`, `ui/Readiness.tsx`), then password (`ui/PasswordScreen.tsx`: Unlock, Upload new file, Start New Database), then load data, then Setup if there are no accounts (`setup/setup.ts`, `ui/SetupScreen.tsx`), else `ui/AppShell.tsx`. `App` owns the one `AiHost` (`ai/host.ts`) and destroys it on `pagehide`.
- **AI (`ai/host.ts`):** one global session. Rebuilt when the context is 80% full (`contextUsage/contextWindow`, or the older `inputUsage/inputQuota`), and once more on `QuotaExceededError`. `renew()` after import, `destroy()` on tab close and import.
- **Crypto and storage:** `crypto/crypto.ts` (PBKDF2-SHA256 600k, AES-256-GCM, base64 `iv||ciphertext`), `crypto/attempts.ts` (wrong-password delay 1s, 2s, 4s up to 30s), `store/kv.ts` (`KV` with an atomic `replaceAll`; `MemoryKV` for tests, `IndexedDbKV`), `store/vault.ts` (`createVault`, `unlockVault`, `changePassword`, `readMeta`; only the vault writes `meta:salt`, `meta:iterations`, `meta:version`, `meta:verifier`), `store/repo.ts` (`loadAll`, `saveSetup`, `commitEntry`, `commitTarget`, `commitReversal`, `commitCorrection`, `commitRename`; `LoadedData` is `{accounts, ledger, budgets, goals}`).
- **Money and dates:** `money/money.ts` (whole rupees only: `parseRupees`, `formatRupees`, `formatCompact`), `dates/dates.ts` (IST `todayIso`, `istTimestamp`, `formatDate` DD/MMM/YYYY, `parseDisplayDate`, `monthRange`), `dates/resolve.ts` (date phrases).
- **Ledger and rules:** `ledger/ledger.ts` (append-only: `append`, `preview`, `planReversal`, `reverse`, `correct`, `balance`, `movement`, `netWorth`, `load`; no edit or delete), `rules/rules.ts` (`validateEntry`, setup balance).
- **Chat pipeline (`chat/`):** `intents.ts` (income, expense, transfer, borrow, repay, revalue, set-budget, set-goal; `TAB_SCOPES`; money flows from the credited account to the debited one), `proposal.ts` (`proposeEntry`: JSON-schema prompt, one retry on bad JSON or a wrong kind of account, then a pre-filled form; outcomes confirm, needs-input, redirect, error), `draft.ts` (`resolveAny` turns the editable draft into a balanced entry, a budget or a goal; account rules below), `amounts.ts` (amounts come only from the user's message).
- **Targets:** `targets/` (`Budget`, `Goal`, `budgetProgress`, `goalProgress`; progress always comes from the ledger).
- **Charts:** `charts/data.ts` (pure builders; `flows` skips opening entries; Sankeys are sources, a "Money in" hub, then targets, so no cycles; revaluations are their own purple kind), `Sankey.tsx`, `LineChart.tsx`, `Bars.tsx`, `palette.ts` (CSS-variable colours), `ui/Dashboard.tsx` (two Sankeys, date range, seven chart tabs).
- **Sample datasets** (`sample/sample.ts`): `buildSample('negative'|'positive', today)` makes opening balances, 25 transactions dated 30 days ago up to today (IST), budgets and goals, all through `resolveAny` so they pass the same checks as chat entries. The negative one ends Dark (net worth about -₹1.02L), the positive one Light (about +₹8.9L). Offered on the password screen as "Try a sample" with the typed password; `App.onSample` nukes any existing store, creates the vault and saves with `saveAll` (in `store/repo.ts`).
- **Ghost's note and tab emojis:** under the title, `theme/GhostNote.tsx` writes a funny line about the user's real situation letter by letter (45 ms a letter, handwriting system fonts: Segoe Print, Bradley Hand, Chalkboard SE, Comic Sans, cursive), with a ghost holding a quill at the pen tip. Lines come from `theme/quips.ts` (`situation` reads net worth, this month's income and spending, top expense, budgets over or near, goals, revaluation and debt ratio; `quips` lists only true lines with real figures; `pickQuip` never repeats the last line). A finished line rests 120 to 240 s at random (`holdMs`), fades, and a new one is written. Crossing into another Net Worth State rewrites it at once. Screen readers hear each line once, complete. The main tabs carry Halloween emojis (`EMOJI` in `ui/AppShell.tsx`, `aria-hidden`, with a `.tab-label` span for the name) that wiggle on hover and float on the open tab.
- **Site header** (`ui/SiteHeader.tsx`, `theme/header.css`): a fixed floating pill on every screen, mounted in `main.tsx` above `App` inside `.app-frame` (which leaves room for it). Shows the title, `v` + the `package.json` version (injected as `__APP_VERSION__` by `vite.config.ts`, declared in `src/globals.d.ts`), "by Julian Frank", the GitHub repo link and "Made with Kiro" (kiro.dev); links open in a new tab. Always crypt-coloured with a travelling rim light, a drifting wisp and a bobbing ghost. Wraps to two rows under 520px. The main app's own `h1` is visually hidden so the title is not shown twice. **Title rule:** "My Money Manager" while net worth (as of today, IST) is above zero, otherwise and on every entry screen "Scary Money Manager" (`ui/title.ts`: `appTitle`, `setAppTitle` also sets `document.title`; `App` works it out, the header reads it with `useAppTitle`).
- **Entry screens (the crypt):** `theme/Crypt.tsx` (`EntryStage` wraps the loader, password, loading and Setup screens in `App.tsx` and sets `data-theme="crypt"`; `CryptScene` draws moon, stars, fog, graves, a pumpkin, embers and five flying ghosts; `KiroGhost` has moods happy, shy, worried, cheer, sleepy and lantern) and `theme/crypt.css`. A guard ghost on each card reacts: a lantern while loading, eyes covered while the password is typed, a head shake at a wrong password, a loop when the books balance. Always dark and separate from the main app's net-worth themes. Design notes: `design/entry-theme.md`. Screenshots: `node e2e/shots.mjs` after a build.
- **Theme:** `theme/theme.ts` (`netWorthState`, `useTheme`), `theme.css` (all colours are CSS variables per `data-theme`), `Decor.tsx`, `events.ts`, `EntryAnimation.tsx`, `ui/AnimatedNumber.tsx`.
- **Export and import:** `export/format.ts` (`exportWithCurrentPassword`, `exportWithNewPassword`, `parseEnvelope`, `openExport`, `importExportFile`), `validate.ts` (`validateItems`, `ImportError`), `template.ts` (the downloadable Export Template), `download.ts`, `ui/DataPanel.tsx` (the "Data and password" tab, the last main tab: export, template, import, change password, AI check, start over). On import the AI session is destroyed before the store is replaced, chat transcripts are dropped (the `AppShell` key changes), and a fresh session starts. The file's password becomes the session password.
- **Golden sentences:** `golden/golden.ts` (36 cases against made-up accounts, `runGolden`, `formatReport`), `ui/GoldenCheck.tsx`.
- **Tests:** next to the code (`*.test.ts(x)`). React tests start with `// @vitest-environment jsdom`; jsdom has `crypto.subtle`, so they can use a real `MemoryKV` vault. Tests use 1000 or 100,000 PBKDF2 iterations for speed. End-to-end tests are in `e2e/`.
